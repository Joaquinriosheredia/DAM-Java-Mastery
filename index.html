vibe-guard

Detecta patrones que pueden pasar los tests y fallar en producción, sobre todo bajo carga, en backends Java/Spring y Python async. Son frecuentes en código generado con IA, pero no detecta autoría ni lo intenta. Cada hallazgo separa detección, impacto (medido o «documented mechanism») y reproducción. Estado actual: Fase 1 del roadmap, fiabilidad y precisión.

Un comando para los dos motores: detecta qué lenguajes hay en el árbol, ejecuta cada motor con su CLI publicada y da un solo informe (texto, JSON común schemaVersion 1 o SARIF 2.1.0 con un run por motor) y un solo exit code. El SARIF de dos runs se probó en GitHub Code Scanning.

JARVIS

Asistente de voz personal en español para Windows: escucha por micrófono, decide qué capa debe responder y actúa con 46 tools (correo, calendario, archivos, música, git, tests y visión) detrás de un gate de permisos.

jarvis-voice-platform · un turno
🎙 Micrófono → Whisper local (umbral de confianza)
 
→ Router de 3 capas
   · atajo tool directa, sin LLM
   · local qwen2.5:3b en Ollama
   · claude Claude Haiku 4.5 en streaming
 
→ tool_use → gate de permisos
   "confirmo envío" leído del micrófono,
   un solo uso, caduca a los 120 s
 
→ TTS por frases (Piper · ElevenLabs opcional)
→ UI Electron vía WebSocket local
 
✓ Ran 634 tests ... OK
✓ Evals: ruta 60/60 · tool 60/60 · gate 60/60
(la métrica tool usa un mock del modelo)
🔐
46 tools con gate de 4 niveles
22 READ · 3 WRITE · 17 EXTERNAL · 5 DESTRUCTIVE. Las acciones irreversibles y las capturas de pantalla piden la frase exacta por voz; el modelo no puede fabricarla.
🛡️
Defensa ante prompt injection
Destinatario resuelto por el sistema, no por el modelo · allowlist de proyectos · git sin shell ni hooks · secretos redactados antes de llegar al modelo · WebSocket solo en 127.0.0.1.
📊
Observabilidad por turno
Latencia por fase, tokens con caché y coste estimado en un log JSONL con replay (p50/p95). Turnos privados: solo metadatos.
🧪
CI en GitHub Actions
Tests con mocks en Windows sin red ni claves · doctor.py --json · escaneo de secretos con gitleaks.

Límites conocidos: solo Windows, un usuario y una máquina; cuando el router elige Claude, lo dicho y lo que leen las tools se envía a la API de Anthropic.

Comportamiento ante fallos

Fallo de sección = no se publica
Si Ollama falla, la sección puntúa 0, cuenta en la media y bloquea la auto-publicación (ADR-002). Es el escenario cubierto por test automatizado.
Timeouts en git
30 s para pull/add/commit y 60 s para push; un TimeoutExpired aborta la publicación con log (ADR-003).
Sin procesos huérfanos
El orquestador mata el grupo de procesos entero (killpg) y el lock solo se libera ante un proceso muerto confirmado (ADR-003).
Rutas portables
Rutas resueltas desde Path(__file__), con overrides por variables de entorno (ADR-004).

Scripts Python locales que se invocan a mano: sin despliegue en la nube ni servicio en producción.
